# 权限与信任边界

状态：设计 v1。M1 已实现 grant 记录、权限求交和安装内权限校验；路径/域 scope 在宿主支持前会被拒绝，完整调用 broker 尚未实现。本文件是插件平台授权语义的单一来源。用户已选择“分级授权”，不是所有写操作永久禁止，也不是安装一次就无限自动执行。

## 1. 有效权限是交集

一次调用可执行的范围为：

```text
安装已批准权限
∩ Bot 已获能力
∩ 经认证的当前请求者权限
∩ 输出受众允许的数据范围
∩ 指定账户 / 设备 / 资源授权
∩ 当前任务、规则、有效期、额度
∩ 宿主不可降低的安全策略
```

缺一项即拒绝或请求授权。没有身份映射的 QQ/平台用户按最低权限处理；模型、插件、Webhook payload 不得通过填写 owner/admin 字段变成主人。Bot 之间委派传播原始请求者和受众，不能变成权限洗白。

权限由宿主 broker 在接收和真正派发时检查；批准后参数、目标账户或接收方变化必须重新批准。queued 工作不能使用撤销前缓存的 allow 结果。UI 隐藏按钮不是安全检查。

## 2. 动作与默认策略

| effect | 例子 | 默认规则 |
| --- | --- | --- |
| read | 搜索、查看歌单、读取已授权账户消息 | 仍需数据域和受众授权；授权内可自动 |
| draft | 回复草稿、歌单建议、内容计划 | 不产生外发；保存位置也必须有权限 |
| control | 播放/暂停、音量、普通灯光 | 已选择设备和明确规则内执行；勿扰和过期限制 |
| write | 收藏、建歌单、修改资料/商品 | 默认审批；可授予特定账户、资源和额度规则 |
| send | 回复 QQ、发布内容、发评论 | 默认审批；常规自动回复可显式范围授权 |
| delete | 删内容、数据或任务 | 明确目标/影响范围，默认逐次确认 |
| financial | 付款、下单等资金行为 | 单独确认，不继承“允许自动回复” |
| security | 改密码、换密钥、门锁/安防敏感操作 | 单独确认，不能由插件降级成普通 control |

分类不是严格大小排序；播放可能打扰别人，读取可能泄漏隐私。宿主根据资源敏感性提升要求，插件不能用 read/control 掩盖账号写入或安防行为。改价、交易、批量发布规则需明确商品、金额/数量、期限与撤销方式。

## 3. Grant 记录

每份授权至少记录：grantId、workspaceId、安装/版本范围、Bot、principal/audience、账户/设备/资源集合、动作集合、参数限制、额度、开始/到期、批准者、批准内容摘要、authorizationEpoch、状态。

- 空资源集合表示没有权限，不表示所有。
- `allow-once` 在派发时原子消费，失败是否返还取决于是否确定无效果。
- `allow-scoped` 可限定群、发言者、收件人、商品、每天数量和时间窗；不提供含义模糊的“永久全权”默认选项。
- 安装更新新增权限、切换源、变更作用域时重批；已有 grant 不能自动覆盖。
- 账户换绑、退出登录、Bot/插件停用、规则关闭时撤销相关 grant 与短期 token。
- 审批中心显示原始发起者、代理 Bot、插件、账户、具体动作和不可逆影响。

复用现有 `outbound-hold`、`decision-log`、`request-auth` 和 MCP gate，不建第二条绕过审批的外发路径。既有安全底线继续有效。

## 4. 凭据与平台身份

凭据仅存服务端 vault，桌面优先系统密钥服务；服务器使用受保护密钥和低权限文件/ACL。POSIX 0600 不代表 Windows ACL 已正确配置，须分别测试。环境变量、子进程 argv、协议日志和前端配置不得带明文秘密。

通常插件拿凭据引用，由 broker 将鉴权注入已允许的上游请求。需要直接处理 Cookie/token 的协议适配器必须申明例外，按最小账户/目标域交付，标明风险。只允许向对应已验证目标发送凭据，重定向必须重新校验，跨域不得沿用鉴权。

不自动扫描浏览器登录态。用户选择账号并完成登录/显式导入后才建立连接。平台账号身份不等于 EAC 主人身份；需要独立映射和验证。

## 5. 共享记忆与外部请求

私有记忆、具名共享空间、当前会话记录和公共知识是不同数据域。空间成员权限为 read/read-write，但查询还需要当前 principal 和 audience 可见性。

- 平台消息不默认进入主人 About me；现有全局注入路径也须按平台请求者过滤。
- 群聊学到的事实默认限制在对应群/项目，不能成为所有 Bot 都可披露的主人事实。
- 群成员点歌可以提供本次风格要求，不得改变主人的长期喜好。
- 共享空间通过代理访问，不挂载给不受限 CLI/文件工具；全文搜索、向量索引、自动召回、工具检索均使用相同 ACL。
- 撤销增加 epoch，作废 token、缓存与待派发检索。现有 provider session 含旧数据时中断/重建，必要时拒绝继续复用。
- 发送响应前再验证受众与 epoch。已传给模型或第三方的数据无法撤回，文档和界面不能宣称完全遗忘。
- 原文删除后清理可追踪的派生索引/摘要；历史对话的保留与外部模型留存须单独说明。

健康、私人聊天和交易资料默认不共享；发送到 OFM 或其他模型是对外披露，需符合该空间的数据出口策略。免费模型不能绕过此策略。

## 6. 网络与文件系统

安全模式需要 OS 层强制：进程不能绕 broker 直接联网、读同用户秘密文件或逃逸挂载。只清环境变量或包装 fetch 不够。无法强制时报告真实模式，所需安全隔离不满足则拒绝运行。

外网默认拒绝，逐域逐协议授权。禁止访问元数据地址和未批准 loopback/内网；用户明确连接局域网 Home Assistant 等服务时建立专用范围例外，不能放开整个网段。解析 DNS 和每次重定向均核查目标，防止 rebinding/SSRF。

宿主只发放预先批准的文件句柄和插件命名空间目录；执行路径规范化，拒绝 traversal、symlink、junction、设备路径和跨卷逃逸。安装器不能继承 root 运行社区代码。

## 7. UI 与扩展内容

沙箱 frame 不得得到 window.ogb、宿主 Cookie 或通用 fetch。postMessage 验证 source、会话 nonce、方法 schema 和预算，不因 Origin 为 null 就放行所有来源。数据与动作分别授权；面板展示一个按钮不代表拥有执行权。

主题只提供合法 token 和受限布局；审批、身份、签名状态、危险按钮和安全模式为可信外壳，不可被第三方覆盖。外部图标/截图必须有受限获取和缓存，避免浏览市场就向任意追踪域发送身份数据。

外部文案、字幕、消息、歌词和模型生成面板均视为不可信数据，不能成为新系统指令。对这些内容的解析不会授予工具权限。

## 8. 故障、停止与审计

- 认证、权限、参数校验或隔离异常：fail closed。
- 装饰性 UI 或非必要观察 hook 异常：移除贡献并显示故障，不停止无关 Bot。
- 外发已派发但响应丢失：indeterminate，核验后才决定是否重试。
- 插件停止：拒绝新调用、撤销 token、取消订阅和规则入口，对已发生外部动作不伪造回滚。
- 用户拥有一键暂停全部自动外发和全部第三方插件的入口，不依赖故障插件自身响应。

每次 allow/deny/审批/撤销/外发结果记录关联 ID、动作、目标标识、策略版本和脱敏结果；不写凭据、完整私信或健康正文。审计保留期与用户数据删除策略分开说明。

## 9. 非目标

不实现验证码或平台安全措施绕过，不以更换代理/设备指纹逃避平台限制。不因用户自装就免除许可证或账号使用条款检查。对合法、已授权的自动回复和运营动作按可用接口逐项实现，而不是把所有自动化一概禁用。

[安全审核清单](security-review.md)和[集成验收](../verification/plugin-integrations.md)必须覆盖这些边界。
