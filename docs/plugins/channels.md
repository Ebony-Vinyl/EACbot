# 扩展渠道、安装与更新

状态：设计 v1。Ed25519 目录验签、HTTPS 有界拉取、渠道持久化、制品摘要校验、安全解包、安装/更新/回滚和撤回拦截已实现；独立扩展仓库与默认社区签名目录已上线。渠道仅负责分发，不授予插件运行权限。

默认渠道：`eac-community`，目录 `https://raw.githubusercontent.com/Ebony-Vinyl/eacbot-extensions/main/catalog/catalog.json`，密钥 `eac-community-v1`，信任级别 `reviewed`。公钥在扩展仓库 `keys/community-public.pem`；私钥只在 GitHub Actions Secret 和本机安全目录，不进入任一仓库。渠道缺失且未被用户删除时自动写入；删除记录会持久化，不会自动复活。

## 1. 渠道对象

渠道保存 `sourceId/name/indexUrl/trustedKeys/lastAcceptedSequence/expiresAt/enabled`。默认社区渠道在发布时内置根信任；自定义 HTTPS 渠道需展示来源、所有者声明和公钥指纹，由用户建立信任。URL 安全不等于包安全。

生产渠道不接受明文 HTTP；本地开发目录/loopback 调试单独开关且标注未发布，不冒充已审核渠道。凭据化私有源的秘密仅在 vault，URL 中不能包含 username/password/token。

同一 pluginId 来自多个源时并列展示，安装身份绑定 sourceId。一个源不能自动覆盖另一个源的安装；换源按重新安装和数据兼容流程确认。

## 2. 签名索引协议

索引信封为 `schemaVersion/keyId/algorithm/payload/signature`，算法固定 `ed25519`。签名覆盖 payload 的 canonical JSON：对象键按码点排序、数组顺序保留、`undefined` 字段省略。先验签，再严格解析 payload。发布脚本与 EAC 校验器使用同一 canonical 规则；修改规则必须同时升级 schema 和签名实现。

payload 包含：
- sourceId、递增 sequence、issuedAt、expiresAt。
- 插件条目及版本：pluginId、SemVer、manifest 摘要、精确源码 revision。
- 每个平台制品：HTTPS URL、sha256、压缩/展开大小、支持平台、API 范围。
- 审核级别、审核时间和声明范围；签名只证明发行者，不等于代码安全。
- revoked 列表：插件/版本/摘要、原因与日期。

客户端保存最高接受 sequence，拒绝回退、未知密钥和过期更新；允许用户回滚代码版本不等于允许回滚索引。索引最大 8 MiB，拉取超时 10 秒，默认每 6 小时刷新，可手动重试。以上为 EAC 设计默认值。

新渠道首次信任不能依赖被同一次未知索引自行声称的“官方密钥”。显示指纹并由用户确认；维护默认源时通过宿主发行链分发根密钥。

## 3. 轮换、撤回和离线

正常轮换由旧信任密钥签署新密钥与生效区间，过渡期双签。旧密钥泄漏时不能仅信任旧密钥签出的替换，需要宿主受信更新或用户核对新指纹的恢复流程。

撤回阻止新安装/启动/更新；活动实例撤销调用权限并停止外发，退出时保留数据与审计。不借撤回功能删除用户文件。

网络离线时可查看已缓存目录，但明确“缓存/信任状态最后检查时间”。过期索引不可授权新安装或升级。已安装且未被本地已知撤回的版本可以按原授权运行，同时显示无法获取最新撤回信息；高风险部署可设置更严格的离线停用策略。不得假称离线仍能实时获知撤回。

## 4. 下载与解包

- 每个下载和解包使用新的空目录；任何构建或检查脚本位于不同受信目录。
- 下载最多 3 次重定向，每次重新检查协议、DNS、地址范围、大小和敏感鉴权；不跨域转发凭据。
- 默认制品压缩上限 100 MiB、展开 500 MiB、10,000 文件、压缩比 100:1；大型 .NET/原生包需审核过的单独额度，不让包自己提高限额。
- 校验摘要后解包，解包器逐路径检查，拒绝 traversal、absolute path、symlink/hardlink/junction、Windows ADS 和保留设备名。
- 不执行安装脚本、包入口或自定义解压命令。安装与构建是两件事。
- 格式、权限、依赖和兼容校验失败时保留明确错误，不留下部分 active 版本。

## 5. 安装事务

```text
选择精确版本与来源
→ 验证索引、摘要、manifest、平台和依赖
→ 显示权限、许可证、运行环境、隔离级别
→ 用户批准安装
→ 原子登记 installed-disabled
→ 配置/登录、选择账户、Bot、设备与作用域
→ 用户激活
→ 启动/健康探测
→ active 或明确 blocked/failed
```

取消必须清理该事务独占的暂存目录，不删除其他下载或安装。重启后根据事务日志完成安全恢复；同一 installation 的并行安装/升级互斥。

## 6. 更新与回滚

更新默认通知，不静默扩大权限；用户可启用同源、同权限且兼容的小版本自动更新，仍执行签名、迁移、健康探测和审计。

升级按旧服务排空/停止 → 数据快照 → 工作副本迁移 → 新版探测 → 原子切换。切换失败恢复旧代码与对应数据快照，确保旧消费者不会和新消费者同时处理消息。

无法逆向迁移的数据升级要求显式确认和恢复备份，禁止只切二进制冒充成功回滚。历史凭据不进入普通备份日志；保留策略由安全存储实现。

已批准权限只在明确兼容范围内继承。新增网络域、secret 访问、外发、文件目录或 UI 读取需要重新批准。插件自更新、动态下载执行任意代码不在允许行为内。

## 7. 界面状态

市场显示：来源、版本、已验证摘要/签名、审核等级、许可证、支持宿主、隔离模式、权限变化、安装进度与真实错误。`connected` 是账户状态，`installed` 是包状态，不共用一个含义模糊的“已连接”标签。

来源禁用只停止该源刷新和新安装，不默认卸载已有插件；用户可选择一起停用。需要警告无法继续获取撤回信息。卸载当前主题/布局回退内置；卸载业务插件提示受影响 Bot、任务和面板。
