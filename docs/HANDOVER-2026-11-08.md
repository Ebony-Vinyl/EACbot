# 交接文档（2026-11-08）

面向下一位开发者（人或 AI）。本文只写状态与入口，设计依据见 [DEV.md](../DEV.md) 与 [插件平台验收](verification/plugin-platform.md)。

## 一、本轮交付（上个 AI 的四项“明确没有做”已全部完成）

### 1. 插件工具自动挂载进 Bot 的 MCP 工具列表

- 活跃插件的工具经 `eac-plugins` MCP 服务器进入每个 Bot 回合（与 email/browser/data 同一条 `harness-mcp-proxy` 通道，新增 `plugins` kind）。所有引擎驱动零改动获得插件工具；用户自己的工具选择（tool scope）对它同样生效。
- 授权模型：`read`/`draft` 效果回合内自动放行（宿主在内存中发回合 grant，不落盘、回合结束即销毁）；`send`/`write`/`control`/`delete`/`financial`/`security` 需要主人发 grant——principal/audience 是 `bot:<botId>`，发给某个 Bot 后它所有会话可用，可设有效天数与最大次数。
- 关键文件：`server/host/plugins-mcp.ts`（挂载与 tools/call 代理）、`server/harness-mcp-request.ts`（中继）、`server/plugins/registry.ts`（`callTool` 接受宿主持有的 grant）、`server/plugins-instructions.ts`（模型侧说明）。
- **已实测**：隔离 fixture 中安装并激活 `eac.health` 后，真实 turn 的 `--mcp-config` 里出现 `eac-plugins`（与 agents/phone/data 并列，经 mcp-gate 包装）。

### 2. 平台入站事件 → Bot turn

- `POST /api/platforms/inbound` 把 `delivered` 事件投给绑定 Bot：每个平台会话一个持久线程（`platforms/threads.json`），`startTurn` 以 `unattended` + `automationSource:"webhook"`（不可信数据边界）运行；回复在回合 settle 后写入 per-account outbox（`platforms/outbox.json`）。
- 桥协议：`GET /api/platforms/accounts/:id/outbox?since=<id>` 拉取 → 送达后 `POST /api/platforms/accounts/:id/outbox/ack` 确认；忙/超限返回 409 且事件不被消费，可原样重投。
- 关键文件：`server/host/platform-inbound.ts`、`server/plugins/platform-outbox.ts`、`server/routes/platforms.ts`（`inbound`/`outbox` 依赖注入）。
- **已实测**：QQ 账户 → 绑定 → 入站 202 → fake 引擎回复 → outbox 收到 → ack 清空 → 同 eventId 重投返回 `duplicate`。

## 二、用户入口（界面上在哪）

- 侧边栏拼图按钮 → 应用面板 → 顶部两张卡片：**扩展**（ExtensionsCatalog：渠道/目录/安装/更新/回滚/本地包）与**平台账户与共享记忆**（PlatformAccountsPanel：连接 QQ/B站/闲鱼/抖音/小红书/贴吧账户、绑定 Bot、看板）。
- 扩展中心 → 已安装插件行内“授权”按钮 → 工具 × Bot 发 grant（`PluginGrants.tsx`）。
- 带 `platformBinding` 的 Bot 在侧边栏显示平台徽标（`PlatformBadge.tsx`）。
- 进程插件需服务环境变量 `EAC_PLUGIN_PROCESS=1`（fixture 启动器已白名单透传）。
