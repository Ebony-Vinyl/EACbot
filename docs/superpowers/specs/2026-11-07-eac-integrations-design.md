# 业务插件与跨模块联动设计

日期：2026-11-07。状态：计划实现，不是已验证能力清单。[总体架构](2026-11-07-eac-plugin-platform-design.md)规定合同与边界，[权限规范](../../plugins/permissions.md)规定授权。

## Context

模块必须进入 Bot 的会话、记忆、任务、用量和权限体系。统一插件接口用于解耦，不应成为重建每个成熟项目的借口。音乐直接改造 KugouMusic.NET；已有调度、记忆、模型驱动、TTS、桌宠尽量复用。

## 1. 跨模块共同规则

- 工具由已授权 Bot 调用，参数包含明确目标和操作身份；后台事件建立受限 principal/audience。
- 平台账户可授权现有 Bot，或绑定左侧独立平台 Bot；安装实例与账户/Bot 分离。
- 会话、工具、看板和任务引用同一服务状态，不各自创建队列、账本或任务执行器。
- 所有状态变化关联 traceId/taskId/accountId，外发带幂等键；indeterminate 必须核验。
- 私有记忆与具名共享空间分离；共享偏好不授予账户权限，群成员不继承主人身份。
- 插件缺失时降级可解释，Bot 不向模型宣告不存在的工具。

## 2. OFM / 用户自定义模型

OFM 指 [dsh-our-free-model](https://github.com/Ebony-Vinyl/dsh-our-free-model)，不是其他缩写。插件身份 `eac.provider.ofm`。

### 2.1 接入方式

复用现有 OpenAI-compatible 驱动和供应商注册表。提供 OFM 与用户自定义 Base URL、密钥、模型选择、连接测试、限额状态；不修改用户其他模型配置。模型供应商与 Agent 引擎分开，不能把“连接模型”当成另一套 Bot。

公开仓库已能支持研究文本/视觉与兼容网关路径；用户所述服务器 New API/NVIDIA 的 TTS/STT/视频能力是额外目标。实施前通过受控配置/接口文档核实端点、模型、编码、采样率、分片、取消和计费字段。模型名或 `/models` 列表不能证明模态可用。

不移植非必要的客户端伪装或限制规避；EAC 连接用户有权使用的网关。真实端点/密钥只放运行时配置，不放仓库。

### 2.2 多模态合同

每个模型描述 input/output modalities、支持接口、流式方式、tools、上下文/输出限制、格式和 usage 单位。capability 状态为 configured/verified/unavailable，未验证的界面明确标注。

对 401、403、429/Retry-After、空流、断流和畸形响应有结构化处理；不无上限自动切免费渠道。模型路由 fallback 不能改变用户数据出口策略。健康/私人记忆不可因“免费”默认上传。

## 3. 实时语音与桌宠

保留 `server/tts/index.ts` 现有七类 provider 和旧播报路径。流式能力注册到统一接口，Pipecat 作为可选独立语音服务，不能另外启动一个不受 EAC 权限管理的 Agent。

先交付真正增量合成/播放，再交付可打断语音输入。音频元数据含 sessionId、utteranceId、generation、sequence、format、sampleRate、channels 与时间戳，音频走二进制通道；控制与大音频分开，不能通过无限 base64 SSE 堆内存。

客户端有有限 jitter buffer、背压和取消；旧 generation 音频直接丢弃。provider 不支持流式时回退并标“分句播报”，不能将全量音频切片冒充实时。

语音输入复用可用转写合同；VAD、AEC、半/全双工分别声明。AEC 不可用时维持半双工，不能承诺扬声器环境可靠打断。桌宠根据 TTS 音频包络驱动嘴形和说话状态；没有音素时间戳时不声称精准音素级口型。

音频焦点由一个宿主服务协调，Muse 与 TTS 只申请/释放 lease。桌面及浏览器按用户授权选设备，服务器本身不假定有扬声器。浏览器手势不足返回等待用户操作。

## 4. EAC Muse：直接改造 KugouMusic.NET

### 4.1 实现范围

以 [KugouMusic.NET](https://github.com/Linsxyx/KugouMusic.NET) 的精确 revision 为基础，复用许可允许的酷狗登录、搜索、推荐、歌单、歌词、队列及播放实现，保留署名和文件级许可。若 README 使用声明与 LICENSE 不一致，发布前明确适用许可，而不是自行断言可任意分发。

不引入 Music Assistant、Navidrome 或替代来源，不先建通用音乐平台。上游 .NET/Avalonia 与 EAC React/Node 不同：保留可用 .NET 服务实现，增加最薄的请求/事件桥，EAC 实现统一面板和对话卡；不要为了统一语言重写成熟业务，也不能嵌一个独立窗口就宣称联动完成。

包随附实际目标平台需要的 .NET 制品/运行说明，不能让用户安装后才发现隐式依赖。服务器负责账户和控制；用户选择的客户端负责出声、音量和播放回执。若上游播放实现只能原生运行，应作为桌面端适配与 browser 播放适配分别验证，不伪称已有服务接口能直接输出跨端音频。

### 4.2 六层深度联动

| 层次 | 必须交付 |
| --- | --- |
| 对话上下文 | “这首”“刚才那首”“先播完再切”绑定实际 trackId/queueItemId/sessionId/revision，不靠模型猜 |
| 偏好与记忆 | 区分临时要求、经同意长期偏好、弱行为信号；支持查看/更正/删除；群成员不得修改主人偏好 |
| 任务与主动性 | 专注/休息任务可生成队列与停止计划，复用 RoutineManager；目标设备、时间窗、勿扰、音量上限可撤销 |
| TTS 与桌宠 | 音频焦点协调、说话降音量/暂停，正确条件恢复；桌宠订阅状态，背景音乐不驱动说话口型 |
| 多入口 | 聊天、Muse 面板、QQ、计划任务共用同一播放状态；来源/授权和回声去重一致 |
| 真实反馈 | accepted、待手势、buffering、playing、paused、ended、failed、离线可辨；无回执不报告已播放 |

工具目标集合：搜索、推荐候选、账户歌单、当前/近期播放、队列编辑、播放/暂停/切歌/seek/音量、收藏与歌单写入。模型选择候选需有来源和可用性信息，不能虚构歌曲节奏/情绪/版权。

### 4.3 音频竞争和状态机

播放控制携带 expectedRevision，落后请求返回冲突并取新快照。音频焦点 lease 保存设备、原 session/generation、原音量与恢复策略。用户手动暂停/切歌/改音量时增加 revision，使旧 lease 失效；TTS 结束只恢复仍匹配的状态。

断网或设备离线后控制命令设短期有效期，过期不补播。重复 QQ 点歌复用幂等键，不重复加歌。外部收藏/建歌单结果不明时回读核验，无法核验则暂停，不自动创建多份。

付费/版权限制明确提示，可在用户允许范围选择可播放候选；不自动购买或绕过 VIP。QQ 分享链接、本地播放、发送音频三种能力分别验证和授权，不能相互冒充。

### 4.4 任务示例与实施分工

“专注两小时，不要人声” → 获取可验证候选/用户偏好 → 创建队列 → 确认设备与主动播放授权 → 启动任务 → 安排停止 → 保留实际结果。音乐不符合要求时让用户更换，不谎称识别了没有数据的音乐特征。

“这首不喜欢，后面换轻一点” → 绑定当前歌曲快照 → 调整队列 → 将临时偏好用于当前任务 → 仅按记忆授权保存长期偏好。

插件 SDK、安装、模型工具、事件与媒体焦点合同就绪后，派专门实现智能体直接移植改造；独立验收智能体测试六层联动并反馈修复。当前文档编写不委派。验收必须包括实际音频播放，不能只验证 JSON 成功返回。

## 5. QQ / SnowLuma / MaiBot / AstrBot

提供通用 Channel Adapter，兼容官方 QQ Bot 与用户自行部署的 SnowLuma OneBot v11 连接。SnowLuma 是否允许特定分发/商业场景按其实际许可评估；外部进程不自动免除义务。

保留用户要求的 MaiBot/AstrBot 可选接入：作为独立运行框架的桥接/委派路径，而非把两个框架嵌进 EAC 核心。每个会话选择 EAC 主处理或外部 Bot 主处理；禁止双方同时对同一事件自动回复。外部框架不支持必要的身份、回执或取消时标明限制。

账户绑定、群/私聊路由、发言者允许名单、主动回复模式和可调用工具分别授权。私聊/群聊经独立 principal/audience 进入 Bot；附件有类型/体积限制，音频请求按语音能力转换。

QQ 看板显示连接、会话、待回复/审批、失败/重试与模型成本。可创建左侧 QQ Bot，也可授权现有 Bot。QQ 点歌调用 Muse；语音回复可联动 TTS/桌宠，但本地播报不等于已经发给 QQ。

## 6. B站

参考 [dsh-bili-humanism](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism) 和 [dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) 的搜索/阅读、字幕、日报、来源与受控写设计。

Bot 支持订阅/推荐研究、读取可用元数据和字幕、必要的授权抽帧/语音识别、生成含作者/链接/分P/时间点/未覆盖部分的报告。缺字幕时说明理解覆盖范围，不将抽样帧总结说成已看完整视频。

兴趣积累需选择记忆空间，外部字幕内的指令不能影响工具权限。收藏/点赞/投币/评论分别核实接口可用性与账号授权，不由读取授权推导。默认写关闭，额度、最小间隔、去重和回读是工具合同；不明结果暂停。

看板含研究队列、内容详情、日报、兴趣空间与授权；独立 B站 Bot 可在边栏展示。不能以相关开源库存在作为官方接口稳定性的保证，发行前核对依赖维护状态和使用方式。

## 7. 闲鱼、抖音、小红书、贴吧

共享的是账户/消息/内容/草稿/任务/回执合同，不是强行给所有平台提供相同 API。

| 平台 | 首批可验证能力 | 高影响能力 gate |
| --- | --- | --- |
| 闲鱼 | 账户连接、可用消息/商品信息、知识库草稿、范围内自动回复 | 发布、改价、订单/交易等逐项核实接口与授权 |
| 抖音 | 允许读取的内容研究、选题、素材、草稿与计划 | 发布与指标数据依据开放能力，不能由下载器推断 |
| 小红书 | 内容/选题研究、草稿、计划与用户提供资料 | 发布、互动和账号数据逐项核实 |
| 贴吧 | 兴趣阅读、帖子摘要、回复草稿 | 回帖单独授权、限额；遇安全验证暂停给用户处理 |

用户参考的 xyxyxy、xianyu-auto-reply、MediaCrawler、dsh-tieba-dive 放入来源矩阵。无许可证、用途限制或声明冲突必须解决后才能复制/分发；采集工具不等于账号运营 API。禁止 CAPTCHA/风控规避，不将用户 Cookie 发给未授权第三方。

能力分 production/experimental/unavailable，给每项实际证据。接口未证实时提供草稿/人工交接路径，而不是承诺全自动运营。合法已授权自动回复可以实现；不可因为部分上游限制就把用户全部需求改成永久只读。

独立平台 Bot 与现有 Bot 授权两种模式都提供。看板标签和账户隔离见产品设计。模型生成的运营动作也要经过相同审批、预算与重复发送防护。

## 8. Kanban、计划与用量

Hermes 的持久任务、认领租约、心跳、依赖、审查和恢复是参考。EAC 的 `server/runtime/` 拥有实际执行，`RoutineManager` 拥有调度；Kanban 存储任务业务描述和执行引用，不额外运行竞争的 worker/cron。

任务有 revision、负责 Bot、来源、账号、依赖、计划、运行 ID、产物、审批引用和结果。状态转换有白名单；running 由执行器推进，review 需要真实产物，done 不能仅凭模型口头宣称。重启租约和幂等策略防重复外发。

现有定时能力扩展模板/UI，不重新造 clock；时区、DST、漏跑、重试上限、并发和取消必须测试。审批等待不占用无限 worker，不因超时自动批准。

用量继续使用 `appendUsage` 等入口，增加 plugin/installation/task/account/device/modalities 归因，唯一调用身份避免重复收费。多模态用 tokens、characters、seconds 等原单位；成本标明 actual/estimated/free/unknown，保留币种与定价来源，不把 unknown 算成 0。预算能力先遵守现有授权边界，不擅自改 enterprise entitlement。

## 9. 健康、家居与设备

Today.ai 参考长期记忆、主动行动和跨应用关联；灵光参考用户提供官网可证实的产品方向，不能臆造公开健康 API。本轮健康插件先做手工/文件导入、睡眠/活动/习惯趋势和提醒，不自动诊断、开药或改变治疗。

健康记录与普通喜好分域，逐类型授权、可导出/删除、默认不进入平台群聊。模型分析需要出口授权和隐私说明；可以与 Muse 放松建议联动，但不得默认推断疾病或情绪并突然播放。

家居优先 Home Assistant 的公开 REST/WebSocket/MCP。只暴露已选择实体；灯光、温控、门锁、安防风险分级。Homebridge/MQTT 后续按真实需求适配，不先搭全新设备中台。

设备协议覆盖配对、身份、撤销、能力、在线租约、命令 TTL、回执与重复处理；手机/手表未来通过系统授权接 Health Connect/HealthKit 等。当前只做协议与模拟器，不开发原生移动端，也不宣称模拟器证明手表实机可用。

## 10. Tauri 与本地/服务器一致性

保留 React 与 Node；通过 HostAdapter 支持 Web/Electron/Tauri。Tauri 第一平台优先验证 Windows：本地服务监督、端口冲突、单实例、托盘、系统凭据、透明置顶桌宠、音频权限与签名更新。Linux/macOS 单独记录，不以交叉构建等同于运行通过。

本地模式服务在用户电脑，远端模式只通过配对授权使用本地设备。远端不能继承本机登录态或任意文件权限。保留 Electron 兼容直到目标能力矩阵满足，不先删壳再补功能。

## 11. 共用完成标准

每个模块必须有独立停用/卸载、实际依赖声明、隔离 fake 测试、用户可见错误、真实平台限制和跨模块故事。目标是能由用户自然驱动的一个助手团队，而非新增若干互相不知道状态的网页。

验收 ID 与具体操作见[业务验收](../../verification/plugin-integrations.md)，分阶段文件与测试任务见[路线](../plans/2026-11-07-eac-plugin-platform/README.md)。
