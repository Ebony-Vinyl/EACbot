# EACbot 插件优先架构设计

日期：2026-11-07。状态：设计基线，尚未实现。当前交付仅包含文档；不能据此宣称插件市场、共享记忆或 Tauri 已经可用。

## Context

EACbot 要同时服务服务器常驻 Bot 和用户电脑上的本地 Bot。后续业务、模型渠道、平台连接、面板、界面布局和皮肤应通过插件扩展，而不是持续向核心增加平台分支。用户可以通过独立社区仓库提交 PR，在 EAC 界面选择渠道并安装插件。

核心目标是高内聚、低耦合，以及同一 Bot 内的深度协作：QQ 消息可以触发音乐任务，B站研究可以形成记忆和 Kanban 产物，语音和桌宠共享执行状态。QQ、B站、闲鱼等可以是现有 Bot 的工具，也可以是左侧独立 Bot；独立不意味着切断经授权的记忆共享。

本设计合并用户最后确认的要求：Muse 直接复用、改造 KugouMusic.NET，不引入其他音乐后端；必须实现上下文、记忆、任务、TTS、桌宠和 QQ 的深入联动。详见[集成设计](2026-11-07-eac-integrations-design.md)。

## 1. 现状与迁移入口

| 领域 | 现有落点 | 处理方式 |
| --- | --- | --- |
| Bot 与驱动 | `server/contracts.ts` 的 `ProviderAdapter`、`SendTurnInput.integrations`；`server/harness/registry.ts` | 保留运行时，适配插件能力，不重造 Agent |
| MCP | `server/mcp-registry.ts`、`server/mcp-gate.ts`、`server/drivers/turn-mcp.ts`、`server/mcp-oauth.ts` | 作为工具/外部服务协议；MCP 不等于插件生命周期 |
| 审批与审计 | `server/outbound-hold.ts`、`server/decision-log.ts`、`server/request-auth.ts` | 增加插件、账户、请求者作用域，不绕开原审批 |
| 任务与计划 | `server/runtime/`、`server/routines.ts`、`server/routine-schedules.ts` | Kanban 关联现有执行与调度，不重复派工 |
| 用量 | `server/usage-ledger.ts` 的 `appendUsage`、`readUsage`、`summarizeUsage` | 兼容历史账本，增加调用归因和多模态单位 |
| 面板 | `shared/app-frame/`、`src/components/app/app-frame-host.ts` | 复用 opaque-origin iframe、CSP 和 `createAppBridge`/`mountAppFrame` |
| 扩展 UI | `src/components/PluginsPanel.tsx`、`src/lib/app-catalog.ts` | 从硬编码服务卡片迁移到贡献点 |
| 皮肤/页面 | `src/lib/skins.ts`、`src/components/bot-panel/page-registry.ts` | 保留内置回退，增加命名空间注册 |
| 原子持久化 | `server/atomic.ts` 的 `writeFileAtomic` | 安装事务与配置沿用现有可靠写入原语 |
| 社区分发 | `server/team-library.ts`、`server/org-library.ts`、`server/skill-library.ts` | 复用有界读取、摘要与禁用导入的模式，分阶段提取公共代码 |
| 记忆 | `server/memory-store.ts`、`server/memory-forget.ts`、`server/workspace.ts`、`docs/memory.md` | 保留私有 Markdown 与 CAS 写入，新增受控共享空间 |
| 桌面 | `electron/`、`src/types/ogb.d.ts` | 先抽宿主接口，再引入 Tauri，保留现有桥接兼容 |

当前没有通用社区插件运行时和 Tauri 宿主。现有 About me 是跨 Bot 偏好来源，但不具备本设计要求的具名共享空间 ACL，不能直接等同。现有工作区文件工具可接触记忆文件，因此共享空间不能仅靠提示词或 UI 开关保护。

## 2. 推荐架构

```text
浏览器 / Electron 兼容宿主 / Tauri 宿主 / 后续设备
                         │
可信外壳：身份、导航、授权确认、安全模式、插件 UI 容器
                         │
稳定宿主：生命周期、服务注册、能力代理、事件、存储、审计
                         │
一方功能模块：Bot 执行、记忆、任务、模型路由、音频协调
                         │
可安装插件：模型适配 / QQ / B站 / 国内平台 / Muse / 健康 / 家居
                         │
可安装 UI：主题 token / 布局 / 声明式面板 / 沙箱页面
```

“万物皆插件”适用于业务能力和产品表面，不意味着第三方可以替换身份验证、审批、签名检查或安全恢复入口。可信底座必须在没有第三方插件时仍可启动、禁用故障插件并恢复界面。

先用受审查的一方适配器将现有功能注册到同一合同，逐个迁出。不得为追求目录形式一次性搬动全部驱动、记忆和存储。模块数量不是解耦指标：新增插件无需改核心业务、停用不影响无关功能、依赖方向可检查才是。

### 2.1 业务依赖规则

1. 插件调用服务键和版本化 RPC，不能 import 其他插件私有代码或读其数据库。
2. `provides`、`requires`、`optionalRequires` 区分强弱依赖；启动前拒绝依赖环和版本冲突。
3. 必需服务未就绪时不激活；可选服务缺失时只关闭相应功能。
4. 每项注册有 disposer，停用按逆序撤销；任务和资源有归属，不能变成无人管理的后台进程。
5. 同步操作走能力调用，事实变更走事件；订阅事件不授予动作权限。
6. 安全策略由宿主执行；插件 hook 可以收紧但不能把拒绝变为允许。
7. 插件安装不自动授权给全部 Bot，也不自动登录平台或执行任务。

### 2.2 执行模式与真实隔离

| 模式 | 适用对象 | 边界 |
| --- | --- | --- |
| 声明式 | 主题、布局、表单、PanelSpec | 宿主绘制，禁止任意代码、任意 SQL/eval |
| 沙箱 UI | 自带复杂界面的插件 | opaque-origin iframe、严格 CSP、校验消息来源；不注入桌面桥 |
| OS 受限进程 | 社区后端插件、随附服务 | 独立身份/目录、限制挂载与出口、资源限制、能力代理 |
| 显式可信本地进程 | 用户选择的本地服务，宿主不能提供所需隔离时 | 清楚标注实际权限，不冒充安全沙箱；需要单独信任确认 |
| 一方内置适配 | 已审查的现有业务 | 允许进程内注册；依然受合同与依赖边界测试约束 |

子进程只是故障隔离，不限制其读取同用户文件、环境、网络或启动其他进程。Linux 优先复用可行的 OS/容器隔离机制；Windows/macOS 逐项探测能力。请求隔离不可满足时返回 `SANDBOX_UNAVAILABLE`，不得静默原样启动。即使显式可信，仍不继承宿主秘密环境或管理员凭据。

## 3. 实体模型

| 实体 | 主键 | 含义 |
| --- | --- | --- |
| 插件定义 | `pluginId` | 发布者命名空间内的稳定身份，如 `eac.muse` |
| 安装 | `installationId` | 某工作区中固定来源和版本的一份安装 |
| 工作区 | `workspaceId` | 授权与数据隔离边界 |
| 平台账户 | `accountId` | 连接、认证和状态，秘密字段不进入客户端投影 |
| Bot | `botId` | 复用现有 Bot；可有平台绑定而不是新物种 |
| 记忆空间 | `memorySpaceId` | 具名知识集合及成员/受众 ACL |
| 任务/调用 | `taskId` / `requestId` | 调度执行与单次调用身份，关联 `traceId` |
| 设备 | `deviceId` | 配对身份、能力、在线租约与播放目标 |

插件、账户、Bot、记忆空间是四个独立对象。一份连接器安装可服务多个账户；一个账户可被多个 Bot 获授权使用，但每条入站事件只能有一个主处理者。跨 Bot 协作必须显式委派并传播受众/权限约束。

## 4. 平台 Bot 与入站路由

接入平台后选择“授权现有 Bot”或“创建独立平台 Bot”。后者自动建立名称、头像、平台标识、工具默认集和平台看板，用户仍能修改模型、人格、任务和边栏位置。

入站处理顺序：验证连接身份 → 解析账户/发送者/群或私聊范围 → 去重 → 匹配确定路由 → 建立低权限请求者上下文 → 调用主 Bot。路由多重匹配必须有显式优先规则或报配置冲突，不能广播给所有 Bot 自动回复。

事件幂等键由平台事件 ID、账户和会话范围构成。回声标记避免自身发出的消息触发循环；委派有跳数/次数限额。没有可靠平台事件 ID 时定义稳定内容/时间窗口策略并记录可能误判，不能宣称严格 exactly-once。

隐藏仅改变边栏可见性；暂停 Bot 停止新派工；解绑撤销账户授权及路由；停用插件停止其能力和订阅；删除 Bot 单独处理任务与私有数据，不删除别人的共享空间。

## 5. 共享记忆与请求者边界

### 5.1 存储与检索

保留现有 Bot 私有记忆。新增具名共享空间，成员权限为 `read` / `read-write`。条目含作者 Bot、来源引用、创建时间、revision、敏感标签、受众、到期时间和删除标记。平台凭据不得进入记忆；默认不把整段私信或全部历史同步过去。

检索必须同时满足：工作区、Bot 成员权限、当前请求者身份、输出受众、数据用途与授权有效期。群成员可以请求点歌，不等于可以要求读取主人的音乐私密记录、健康数据或全部共享知识。

不沿用“把所有共享内容拼进系统提示词”的实现。共享存储不挂载到不受限的 Bot 工作目录；受控读取、自动召回、文件工具、搜索索引和上下文注入走同一策略。如果驱动不能限制文件访问或清理会话上下文，不向其提供受限共享空间用于外部请求。

现有 About me 的全局注入也必须在平台入站模式按请求者/受众过滤。不能仅限制新共享接口，却让旧全局偏好泄漏。

### 5.2 写入、冲突与撤销

- 共享写入要求成员写权限及请求者写权限，记录来源；群成员不能修改主人偏好。
- 复用 `writeMemoryDoc` 的 expectedHash 思路，新增存储使用 revision/CAS；冲突返回当前版本，不静默覆盖。
- 不同来源的相反事实并存并标记冲突，模型可提议更正，不能抹掉证据。
- 退出空间立即增加授权 epoch，撤销检索令牌，清缓存和派生索引访问；队列中调用在执行时重新授权。
- 已加载该空间的会话在下一次模型调用前重建允许的上下文；必要时中断当前生成并建立新 provider session，旧 session 不得继续复用。
- 授权撤销后尚未送出的响应再次检查；已向模型、外部平台或其他人披露的内容不能收回，审计中记录边界。
- 记忆副本的引用与派生摘要保留 provenance；删除时处理对应索引、缓存和派生条目。历史对话按独立保留规则处理，不能假称全网遗忘。

## 6. 能力、事件和一致性

能力请求关联 `installationId/botId/accountId/taskId/deviceId/requestId/traceId`，作用域由宿主根据已认证身份构造，不能采用插件或模型任意填写的身份。

结果状态为 `succeeded | failed | cancelled | indeterminate`。异步开始仅返回操作句柄，最终成功必须有完成事件/回执；播放器“开始请求”不是“已出声”。不可确认的外发结果暂停核验而非盲重试。

事件有 schema 版本、生产者、作用域、因果链、序号和有限数据引用。隐私事件只给获授权订阅者，不能在通用 SSE 广播完整私信。重放窗口、队列上限、重试和死信均有界。控制流不依赖事件绝对不丢或跨平台恰好一次。

同一网络/模型调用只有一个计费归属，委派链可显示分摊视图但不能重复累计。任务状态与 UI 都消费同一服务结果。

## 7. 生命周期与数据

正常路径：`discovered → downloaded → verified → installed-disabled → starting → active`。失败、阻断、停用、撤回分别展示原因；详见 SDK 规范。

安装制品只读且按摘要定位，数据按 installation 命名空间存放，秘密由单独 vault 管理。已有配置和数据库不全量迁库。安装/升级记录事务：暂存、验证、依赖检查、停旧服务、状态快照、迁移、新版探测、原子切换。

不兼容升级不自动生效；新权限重新批准；不可逆迁移阻止自动回滚并要求明确恢复方案。卸载默认保留数据，清除数据另行确认。撤回版本禁止新启动，撤销能力并终止其外发，不删除用户数据。

## 8. UI 与宿主

UI 支持主题 token、布局描述、命名插槽、声明式 PanelSpec 和高级沙箱页面。核心审批、身份、权限解释和恢复入口不能被主题覆盖。插件缺失/故障可移除贡献，不使整个 React 树崩溃。

Tauri 通过 `HostAdapter` 实现宿主能力，不重写 Node 服务。先保留 `window.ogb` 兼容及桥接测试；Web、Electron、Tauri 按能力显示功能。服务器不能天然控制访问者电脑；音频/麦克风/本地文件由认证客户端提供。

原生手机、手表本轮只定义协议与模拟测试；不能把现有浏览器/PWA 支持或模拟设备通过写成已交付原生 App。

## 9. 架构决策

| 决策 | 推荐 | 原因及代价 |
| --- | --- | --- |
| 迁移 | 渐进适配，旧功能逐项回归 | 避免一次重写失去现有能力；短期保留兼容层 |
| 插件框架 | 明确合同与服务注册，不整体换用外部 Harness | 复用既有运行时，吸收生命周期思想而非引入第二套核心 |
| UI 安全 | 声明式优先，沙箱为扩展出口 | 能更可靠验收；高级任意 UI 仍有隔离成本 |
| 市场 | 独立仓库、人工 PR、签名索引、固定制品 | 降低供应链变更风险；增加发布维护工作 |
| 账户自动化 | 分级授权，真实能力逐项启用 | 保留自主性，不能承诺不受第三方接口变化影响 |
| 记忆 | 私有 + 显式共享 + 受众交集 | 深度协作而不把平台用户变成管理员 |
| Muse | 直接改造 KugouMusic.NET，联动优先 | 保留成熟功能；需打包 .NET 适配与测试运行环境 |
| 桌面 | Tauri 目标、Electron 兼容过渡 | 避免托盘/桌宠/音频等换壳回归 |

## 10. 质量与发布约束

新路由使用 `createXRoutes(deps)` 并由组合根注册；不能 import `server/index.ts`。保留体积、路由和依赖边界棘轮。注释遵循根 AGENTS，不以注释解释失控的依赖。

配置和接口区分公开投影与秘密字段。新页面中英文文案按 DEV 进入现有 locale 流程；插件语言包单独命名空间。不擅自删除 enterprise 或改变现有授权产品边界。

功能验收必须用隔离 fixture，生产实例仅在正式发布后做获授权的只读健康检查。文档完成不代表任何业务功能已经实现；证据标准见[验收入口](../../verification/plugin-platform.md)。
