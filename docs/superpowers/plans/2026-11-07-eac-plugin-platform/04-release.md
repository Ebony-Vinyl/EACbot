# 发布、预发布与恢复 Implementation Plan

## Context

用户已有服务器部署，但项目规则要求所有变更验证使用隔离 fixture。当前文档交付不连接或修改生产，不在仓库记录服务器地址、SSH 信息、密钥、口令或真实数据。

**Goal:** 用可复现证据发布，并在失败时恢复正确代码与数据，而非承诺固定几秒停机。

**Architecture:** 本地质量门槛 → 独立 staging → 不可变 release → 受控切换 → 只读健康检查；插件发行与主服务发布可分开。

## 1. 文档阶段检查

- [ ] 所有相对链接存在、需求 ID 有阶段和验收项、示例 JSON 可解析。
- [ ] 新增 API/命令标为设计，verification 文档不引用尚未注册的路由或不存在的源文件。
- [ ] 安全术语、实体 ID、状态机、权限策略在文档间一致。
- [ ] 无生产秘密、真实账户数据、内部部署地址或私人文件路径。
- [ ] `git diff --check`；执行可用的文档检查。缺依赖时记录未运行，不能伪报测试通过。
- [ ] 只有文档变化不需要启动服务证明运行行为；不得说业务验收已通过。

## 2. 实施后的质量门槛

```sh
pnpm typecheck
pnpm lint
pnpm i18n:check
pnpm check:contrast
pnpm test
pnpm build
pnpm check:electron
```

按变更平台额外运行包与桌面 smoke。`pnpm test` 自带的 broker/桌面/打包链失败要单独列出；不能只取 Vitest 成功片段。主分支原有失败先保留基线证据，不能随意归因或吞掉。

每个新功能都添加可运行 verification recipe，并保持 `scripts/testing/verification-docs.test.ts`、文件体积/路由棘轮通过。架构边界检查阻止新增平台硬编码或跨插件私有 import。

## 3. 隔离 staging

在用户批准部署目标后先只读核对现有服务、目录、运行用户、Node/pnpm、反向代理和备份。建立独立 staging 目录、临时 HOME/DATA_DIR、随机或专用非生产端口、独立低权限用户；不复用生产密钥或数据。

测试使用 fake 服务及合成数据。若需要外部真实账号/付费模型，明确授权范围、目标、额度与清理步骤；生产群、店铺和真实交易不作自动测试 fixture。

测试必须关闭并清理自己创建的资源，不能按进程名 kill 或删除宽泛 temp 根目录。保留日志与证据，删除敏感 payload。

## 4. 发行制品与备份

- 固定源码 revision、依赖锁与构建环境，不直接部署浮动 branch。
- 在独立 release 目录完成依赖安装/构建，服务运行目录不边更新边构建。
- 备份应用配置、数据与插件安装/状态版本，秘密使用受保护导出方式；备份成功后实际做恢复演练。
- 数据迁移采取 expand/contract；明确旧代码可否读取新状态。不可逆迁移要求维护窗口和已验证恢复步骤。
- 本地桌面包与插件制品分别签名；不要把开发私钥或服务器密钥作为发行密钥。

## 5. 正式切换

用户确认目标/时机后：停止接收新任务 → 排空或安全暂停执行 → 固定待核验外发队列 → 切换 release 引用 → 重启主服务 → 只读健康/版本检查。

启用版本不兼容或新增权限插件仍需独立批准。社区插件不继承 root；主服务逐步迁到专用低权限用户，在 staging 验证目录权限与隔离后再切换。

既有 `git pull → pnpm build → 重启` 流程可作起点，但随着依赖与数据迁移增加，停机取决于实际构建/排空/迁移。缩短停机应依靠预构建与原子切换，记录真实耗时，不预先承诺几秒。

## 6. 回滚与外部效果

只读健康检查失败立即停止新派工，恢复上一 release 与匹配的数据/配置快照，再校验版本与关键只读状态。不可逆迁移必须走恢复演练中确定的路径，不能仅 git checkout。

外部消息、播放、发布和交易不能因应用回滚自动撤销。已派发但不明结果保留核验记录，恢复后不自动重发。授权撤销、渠道撤回与安全 epoch 不随普通代码回滚到更宽松状态。

## 7. 交付报告

交付 revision/制品摘要、部署环境、通过/失败/跳过用例、mock/真实验证分栏、UI 证据、数据迁移记录、备份/恢复路径、停机时间、已知限制和下一步。

[发布验收](../../../verification/plugin-release.md)定义 REL-01…09。只有全部目标关键路径通过且无阻断缺陷才能发行；尚未拿到平台凭据或接口未开放不是“已通过”。
