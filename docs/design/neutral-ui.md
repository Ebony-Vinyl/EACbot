# Neutral UI 前端

本次改动影响范围是 Web 与 Electron 的前端呈现模块。

## 范围

用户确认使用本机 `@neutral-reference/ui` 重写前端，保留现有功能、业务状态、后端接口与明暗主题；覆盖聊天、任务、Agent、电脑、终端、设置和扩展入口。Android 原生界面不在本次范围。

备份位于仓库旁的 `EACbot-backups/20261116-103100-before-neutral-ui`。其中前端归档逐文件核对过 SHA-256，另存已跟踪改动的二进制补丁和未跟踪源码。

## 决定

- 使用随仓库保存的 `vendor/neutral-reference-ui-0.1.0.tgz`，避免依赖另一台机器不存在的绝对路径；包内保留 MIT 与第三方许可。
- 保持 `index.html` → `src/App.tsx` 为唯一主界面。应用导航与会话列表分开，功能页使用整个主工作区。
- 基础 Button、Input、Card 使用 Neutral UI 实现，原组件接口保持兼容。旧页面的语义颜色映射到 Neutral 主题，减少跨模块改动。
- 保留聊天列表、审批卡、附件、电脑控制与现有弹层实现；不重写网络、配对、持久化或执行逻辑。
- 沿用现有皮肤选择的持久化，浅色皮肤使用 Neutral light，深色皮肤使用 Neutral dark。工作区提供直接切换明暗的入口。

比较过另建独立应用、逐页重写业务状态、复用状态并更新呈现三种方式。采用第三种，保留用户已确认的功能和导航修复，避免两套状态再次产生冲突。

## 质量边界

导航即时响应；已有分页、虚拟列表和消息流继续由原模块负责。设备凭据留在原认证模块。新增界面不发送遥测、不访问真实用户数据。组件依赖固定在本地安装包，后续修改仍按业务模块归属维护。

验证最多三轮，覆盖定向导航回归、类型检查、lint、生产构建，以及隔离 fixture 的浏览器桌面/窄屏、明暗主题和关键操作。测试结果另记于验收文档，本文不代表这些检查已完成。

回退时从备份恢复前端与依赖清单；工作区补丁与未跟踪源码单独保存，不使用破坏性的整仓重置。
